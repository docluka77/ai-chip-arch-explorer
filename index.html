当经典 CNN 加速器遇上 Transformer：数据流冲突与算子映射全解

Eyeriss、ShiDianNao 与 NVDLA 均诞生于以局部二维滑动窗口 (2D Sliding Window) 与静态卷积核权重 (Static Weights) 为核心的 CNN 时代。而 Transformer 引入了无空间滑动复用的 $1\times1$ 线性投影、双动态操作数矩阵乘 ($Q\times K^T, P\times V$)、随序列膨胀的 KV Cache 以及全局归约非线性算子 (Softmax / LayerNorm / GELU)。下方交互沙盘逐层拆解三款架构运行 Transformer 时的真实硬件表现。

Stage 1: Q / K / V 线性投影 (Static Weight Matrix Multiplication)

计算密集型 (Prefill) / 访存密集型 (Decode)

将输入 Token 序列张量 X [L, D] 与训练好固定的权重矩阵 W_Q, W_K, W_V [D, D] 相乘。在硬件层面，这完全等价于卷积核尺寸 R=1, S=1、输入通道 C=D、输出卷积核数 K=D、空间像素数为 L 的 1×1 逐点卷积 (Pointwise Convolution)。

Georgia Tech & NVIDIA · MICRO 2019 MAESTRO: Modeling Accelerator Efficiency via Spatio-Temporal Reuse & Occupancy

MAESTRO 数据中心指令 (Data-Centric Directives) 与硬件设计空间探索器 (DSE)

传统循环嵌套 (Loop-Nest) 属于“计算中心”表达，难以直接量化片上多播与归约收益。MAESTRO (MICRO'19) 提出了以数据移动为一等公民的四大原语：SpatialMap(sz, ofs)、TemporalMap(sz, ofs)、Cluster(P) 与指令顺序，将 Eyeriss、ShiDianNao、NVDLA 统一抽象为 YR-P、YX-P 与 KC-P 三类规范数据流，并通过五大分析引擎在毫秒级完成硬件参数空间探索 (DSE)。

MAESTRO 五大核心分析引擎流水线
1. Tensor Analysis (TA)张量维度耦合
2. Cluster Analysis (CLA)多维并行聚类
3. Reuse Analysis (RA)空/时多播与归约
4. Performance (PA)Pipe NoC 屋顶线
5. Cost Analysis (CA)CACTI 28nm 能耗
